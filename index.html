Master's thesis · deep learning, time series

Trading signals across 70 stocks

One shared network labels every daily bar of 70 NASDAQ-100 stocks as buy, hold or sell. I trained 8 architectures under 5 class-imbalance settings (41 runs) and scored them on F1 and on Sharpe ratio, because the two turned out to disagree.

Best composite rank
TCN
Best Sharpe
0.385 TFT + T-SMOTE
Best F1
0.512 TFT + WCE

The weighting that maximized F1 also multiplied trades by 4 to 8 and gave the worst Sharpe. One model's 70.3% accuracy was just "always predict Hold". And CDT-CNN's convolutions could see future bars: a causal rewrite cut its F1 by 0.054 on average.

How it was set up
  • Labels come from a zigzag rule: a buy or sell only where price reverses by at least 1%, so Hold is about 70% of bars
  • Inputs are OHLCV plus TA-Lib indicators; Ichimoku's lagging span is left out to avoid look-ahead
  • Same test year for every model (July 2025 to June 2026). Sharpe ignores transaction costs, so treat the ranking as suggestive
  • Supervised by Prof. Essalih Mohamed, 2025–2026

Personal project · credit risk

CreditLens

A lender loses much more on one bad loan than on one refused good customer (5 to 1 on the standard cost matrix), so I tuned for expected cost instead of accuracy. Built on the 1,000-row German Credit dataset.

Test ROC-AUC
0.76 CI 0.68–0.83
Cost per applicant
0.645 vs 0.70 declining all

The saving over declining everyone is 5.5%, but its 95% interval runs from −9.5% to +19%, so I can't claim the model beats that simple policy on 200 test applicants. The app shows the interval.

How it works
  • Probabilities are calibrated, and the 13% cut-off was picked on out-of-fold predictions
  • One saved model object serves training, tests and the API
  • Sex and age are not inputs and the API rejects them, though the audit still found age disparity coming through other features
  • Pandera checks the data, Evidently checks drift, DVC and MLflow track runs

Personal project · classification, regression, AWS

Car insurance claim risk

I started from a notebook that fit its preprocessing before splitting the data, which leaks the test set. I rebuilt it as two sklearn pipelines and put them behind a FastAPI service on AWS: will this driver file a claim, and how large would it be.

Claim classifier ROC-AUC
0.82
PR-AUC
0.64 27% of drivers claim

Claim size is the weak half. The regressor doesn't beat predicting the average claim ($8,381 RMSE against $8,285), so the classifier carries this project.

How it works
  • Imputing, scaling and encoding live inside each pipeline and are fit on the training split only
  • CDK defines the infrastructure (Fargate, load balancer, S3) and GitHub Actions is the only way it gets deployed
  • Terraform creates the GitHub OIDC role, so no AWS keys sit in the repo
